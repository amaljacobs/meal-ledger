# Technical Plan

## Platform and Baseline

- Platform: Android, phone-first.
- Language: Kotlin.
- UI: Jetpack Compose with Material 3.
- Minimum SDK: API 26 (Android 8.0).
- Target and compile SDK: latest stable SDK installed by Android Studio when the project is created.
- Package name: `com.amaljacobs.mealledger`.
- Build system: Gradle Kotlin DSL and the Android Gradle Plugin generated by the current stable Android Studio template.

Use template-managed dependency versions initially. Add libraries only when a concrete feature requires them; avoid copying a large dependency catalogue into the first commit.

## Application Architecture

Use a simple single-activity, layered architecture:

```text
Compose screen -> ViewModel -> Repository -> Room / DataStore
```

- `ui`: screens, reusable UI components, navigation, and UI state.
- `domain`: models and small use cases only when they remove meaningful ViewModel complexity.
- `data`: Room entities, DAOs, database, repositories, and preference storage.
- `di`: dependency wiring.

ViewModels expose immutable UI state through Kotlin `StateFlow`. Compose screens observe state and send user events back to their ViewModel. Database queries use Kotlin Flow so totals and timelines refresh after every change.

## Persistence

- Room stores `FoodEntry` and `WaterEntry` locally.
- DataStore Preferences stores `UserSettings`.
- Store money in minor units (`Long`), never `Double`, to prevent rounding errors.
- Store instants in UTC; convert to local dates only for display and day-based queries.
- Schema changes require Room migrations once data can exist outside development devices.
- Keep water in millilitres in persistence. User-facing cup and bottle shortcuts convert to millilitres using a configurable cup size.
- The first schema extension, optional protein grams, advances Room from version 1 using an explicit migration and an exported schema test.

## Initial Dependencies

The generated Compose template supplies the Android, Kotlin, Compose, and Material dependencies. Add the following as their corresponding issues need them:

| Need | Library family |
| --- | --- |
| Navigation | Navigation Compose |
| Local database | Room with KSP |
| Preferences | DataStore Preferences |
| ViewModels | AndroidX Lifecycle ViewModel Compose |
| Dependency injection | Manual constructor injection at first; evaluate Hilt only after multiple screens/repositories need it |
| Tests | JUnit, kotlinx-coroutines-test, AndroidX Compose UI test |

## Navigation

Start with four top-level destinations:

- Today
- Summary
- Settings
- Add/edit forms, opened as routes from Today rather than a top-level destination

Navigation routes use entry IDs rather than serialized full objects.

## Quality Gates

Before each pull request or merge to `main`:

1. Run unit tests for changed ViewModels, repositories, or calculations.
2. Run Compose UI tests for changed user flows where practical.
3. Build the debug app successfully.
4. Manually test food and water creation, edit, delete, totals, and a settings change on an emulator or device.
5. Keep all user-visible strings in Android string resources.

Before the first Play internal test:

- Test a fresh install and an upgrade from the preceding build.
- Verify local data behavior across app restart and device rotation.
- Confirm the app works with no network connection.
- Prepare a privacy policy stating that MVP data stays on-device.

## Repository Conventions

- `main` must remain buildable.
- Branches: `feature/<issue-number>-short-description`, `fix/<issue-number>-short-description`, or `docs/<issue-number>-short-description`.
- Commit format: imperative subject with issue reference, for example `Add Room food entry entity (#10)`.
- Keep build artifacts, local SDK paths, signing keys, and release files out of Git.

## Deferred Decisions

- Decide on Hilt only after the repository layer is in use.
- Decide on analytics, crash reporting, backup/export, and cloud sync after the MVP proves useful.
- Decide the release target SDK when generating the initial project, based on the stable Android Studio SDK available locally.
